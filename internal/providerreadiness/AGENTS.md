# Provider runtime readiness

Inspect the provider's resolved family, executable and launch environment.
Provider names are user aliases; infer protocols from explicit inheritance.
Use only local status commands and bounded, cancellable subprocesses. No probe
starts a model conversation or changes credentials. Return a missing credential
verdict only when the native CLI says so. Unknown protocols or wrapper/config
arguments remain explicitly unverified, with a real-task verification hint.

Local configuration is distinct from successful remote inference. Accept the
native CLI's supported login modes equally; subscription-specific onboarding
policy belongs to its own projection. Never return or log native credential
output, environment values or tokens in diagnostic details.

Resolve bare executable names with the effective worker PATH. An explicitly
empty PATH must not fall back to the supervisor process environment.

Hook copy destinations must match the effective session runtime, including
per-agent overrides: local consumers resolve them from the session workdir;
container consumers retain their city-root projection. Keep managed hook
content fingerprints and unrelated user files intact.


Startup update handling recognizes a complete vendor menu before selecting Skip:
heading, numbered update/skip choices and continue footer. Keep polling and
streamed detection aligned. Quoted update text, authentication screens and native
agent questions do not authorize this startup action; never choose Update now.
Move, re-read, and confirm only from the visible Skip row; unknown selection
never authorizes Enter or composer readiness. A stream needing a selection move
hands off to synchronous peeks.

## Native interaction lifetime

A Codex async question remains pending until its native reply or cancellation,
even after the model emits task_complete. Require the process-owned native
occurrence and matching live queue/editor before answering; a completed model
turn alone does not dismiss queued user input. Preserve stale-response refusal
and the ordinary-message guard while a native interaction owns input.

Bind a present native editor counter to the owned request's original batch
position and total, preserving authored title text. A counter-free next panel
can bind only one unique exact pending native title/choice shape, even while
an earlier reply record lags. Ambiguous, stale or mismatched shapes remain
unavailable and authorize no answer keys.

After a successful answer or Submit key, failed verification is
`ErrInteractionOutcomeUnknown`, preserving its diagnostic identity. Classify
that marker before any wrapped stale/refusal/unavailable error and retain the
lane's at-most-once outcome. For approval verification, preserve success only
for a proven missing session; an unavailable observation proves neither success
nor an unsent answer. See `internal/runtime/REQUIREMENTS.md`,
RUNTIME-CONTRACT-020 and RUNTIME-CONTRACT-021.
