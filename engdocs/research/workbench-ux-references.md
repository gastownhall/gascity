# Workbench UX references

Checked 2026-09-27. **Evidence** describes visible first-party material; **Inference** is a proposed Gas City adaptation, not a claim about either product. Vibe Kanban source links below are pinned to commit `4deb7eca`.

It may be private, removed, or otherwise unavailable; **no board contents or UX pattern is inferred from it**.

## Inktri GitHub project view

- **Evidence:** The separately supplied [Inktri project](https://github.com/users/inktri/projects/2/views/1) is accessible in the signed-in browser. Its named views are Backlog, Priority board, Team items, Roadmap, and My items. The Backlog board uses Backlog → Ready → In progress → In review → Done columns, with visible limits of 5, 3, and 5 on Backlog, In progress, and In review respectively. The Priority board currently displays the same status columns; its name alone does not establish priority grouping. No cards were visible in the inspected views, so item-level behavior was not assessed.
- **Evidence:** Team items is a table with an Assignees slicer and columns including Status, Linked pull requests, Sub-issues progress, Priority, and dates. Roadmap is a timeline with date-field and zoom controls. My items is a table filtered by `assignee:@me` and currently reports zero matches. **Inference:** The useful pattern is separate lenses for workflow, ownership, time, and personal attention, with consistent search/filter controls. For the solo-operator Workbench, map ownership to real rigs/sessions and attention to actual Gas City state; show a timeline only when dates are authoritative. Do not mirror empty or misleading views merely for parity.

## Vibe Kanban fork

- **Evidence:** The [fork README](https://github.com/rhar1511/vibe-kanban/blob/4deb7eca8f381f7cbc1f9d15515a9ab8f8009053/README.md) separates planning in kanban issues from execution in agent workspaces, then brings diff review, preview, and PR work into the workspace. The README says Vibe Kanban is sunsetting; treat this as a design reference, not a dependency recommendation. **Inference:** Make Workbench a work-to-execution navigation surface: each Bead should lead to its real detail and related agent/session/review context, without creating a parallel task record.
- **Evidence:** The [kanban guide](https://github.com/rhar1511/vibe-kanban/blob/4deb7eca8f381f7cbc1f9d15515a9ab8f8009053/docs/cloud/kanban-board.mdx) and [board screenshot](https://github.com/rhar1511/vibe-kanban/blob/4deb7eca8f381f7cbc1f9d15515a9ab8f8009053/docs/images/cloud/project-kanban-board.png) show status columns, a search/filter/sort bar, compact cards, and separate Active/All/Backlog/Cancelled views. [Card source](https://github.com/rhar1511/vibe-kanban/blob/4deb7eca8f381f7cbc1f9d15515a9ab8f8009053/packages/ui/src/components/KanbanCardContent.tsx) prioritizes ID and title, then optional preview, priority/assignee, tags, PRs, and relationships; overflow is counted. **Inference:** For a dense Work Queue, put Bead ID/title/status first, expose useful related-state badges, and keep secondary metadata bounded rather than turning every row into a full detail view.
- **Evidence:** The [issue guide](https://github.com/rhar1511/vibe-kanban/blob/4deb7eca8f381f7cbc1f9d15515a9ab8f8009053/docs/cloud/issues.mdx) links issues to workspaces and sub-issues; the [issue-panel screenshot](https://github.com/rhar1511/vibe-kanban/blob/4deb7eca8f381f7cbc1f9d15515a9ab8f8009053/docs/images/cloud/issue-overview.png) keeps the board visible while opening a right-side panel. **Inference:** Preserve queue context when opening a Bead and make dependency/related-entity navigation direct; retain the existing deep-linkable Bead detail rather than duplicating it.
- **Evidence:** The [workspace interface guide](https://github.com/rhar1511/vibe-kanban/blob/4deb7eca8f381f7cbc1f9d15515a9ab8f8009053/docs/workspaces/interface.mdx) and [workspace screenshot](https://github.com/rhar1511/vibe-kanban/blob/4deb7eca8f381f7cbc1f9d15515a9ab8f8009053/docs/images/workspaces-interface-overview.png) use a workspace list with Running/Idle/Needs Attention indicators beside conversation, toggleable changes/logs/preview, and Git/terminal/notes details. The [changes guide](https://github.com/rhar1511/vibe-kanban/blob/4deb7eca8f381f7cbc1f9d15515a9ab8f8009053/docs/workspaces/changes.mdx) provides file-tree diffs and inline feedback. **Inference:** Surface attention-needed state prominently and offer focused drill-downs to existing session, logs, and review surfaces instead of squeezing them into the queue.

**Scope guard:** Gas City's [Workbench guide](../../docs/guides/workbench.md) describes the original read-only slice, but the [current draft Workbench](../../internal/api/dashboardspa/web/frontend/src/routes/Workbench.tsx) also supports status/priority moves and explicit attempt start. Beads remains the durable work authority. Do not copy Vibe's separate issue database, scheduler, or workspace ownership; adapt its information hierarchy and contextual drill-down to Gas City's existing records. Bulk edits need separate authorization and error-handling design.
