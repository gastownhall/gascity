# Preserve a released-bead handoff through a stale fresh-cycle tick

Root: `ga-4488m2l8`

Prepared: 2026-11-20 UTC

Source pin: `3c5036643f10c643749290ec259bf6606f6716c6`

Public tracker: [bug #9320](https://github.com/gastownhall/gascity/issues/9320).

## Problem and intended result

A session can release its work bead while an older reconciler snapshot
still names it as that session's next anchor. The live anchor is open, so
the existing terminal-only check does not stop the fresh-cycle kill. The
session can die before its next hand-back command runs.

The source analysis reports 27 of 46 reviewer hand-backs near such a cycle,
including 20 before any sling. These are the pack-author's historical
measurements, not a new reproduction by PM. Other roles showed the sequence;
their downstream harm was not measured. The current source still has the
legacy terminal-only anchor read.

The fix adds an ownership check to the same authoritative live anchor row.
If the anchor no longer belongs to the session, the stale cycle must not
kill it or apply a session/current-bead reset patch. A genuine reassignment
still cycles when the live anchor belongs to the session and the existing
protections do not apply.

## Preserve the two implementations' existing contracts

| Concern | Legacy | v2 |
| --- | --- | --- |
| Where the live anchor is read | Existing owner/topology probe in `session_bead_cycle.go` | Existing bounded stop-effect probe after the Q1–Q3 rollout |
| New fact | Status and assignee from one uncached owner row | Status and assignee from the same effect-side live anchor row |
| Live anchor released or assigned away | Skip this stale tick's cycle before kill or session patch | Refuse the fresh-cycle stop before runtime call or session patch |
| Genuine still-owned reassignment | Continue existing cycle behavior when other protections do not apply | Continue existing cycle behavior when other protections do not apply |
| Anchor read error | Preserve current fall-through after Q1 | Preserve the deliberate refusal on unreadable/missing/expired facts |
| Identity scope | Existing `sessionAssignmentIdentifiersForConfigInfo` | New anchor-owner row is the architect's decision; existing Q1/Q3 `RefuseScope` is unchanged |

The distinction between error policies is settled in `ga-7fkreih` section
4.4. PM does not replace v2's deliberate refusal with legacy behavior.

proposal does not explicitly select a set for this new anchor-owner row;
`ga-7xk753ec` records that disposition before the v2 work begins.

The source's legacy proposal is reused directly: enrich the existing
terminal-anchor observation with the assignee from its one authoritative
read. Preserve existing self-claim, previous-bead ownership/time, live Q1
claim-scan and scan-failure, terminal-anchor, busy-session and restart
protections. Cache hits or two independent reads cannot substitute for that
one live row.

| Case at the live guard | Required observation |
| --- | --- |
